# 會員自動帶入與分析紀錄

登入後以中央 `GET /v1/me` 的 birthday 及 shown_name（無值才 initials）帶入本人資料，並讀取最近一次本人分析的命盤規則與血型。`user_id` 是唯一資料歸屬鍵；JWT sub 必須與中央回傳的 user_id 一致。網頁的暫存命盤依會員分開，匿名資料僅存目前分頁的 sessionStorage。登入前正在分析的對象會保留為其他對象，不覆蓋中央資料。

姓名是每筆分析的辨識標籤，不影響靈數計算，也不傳給 AI。輸入生日不同時取消本人勾選；同生日的其他對象不會自動歸類為本人。本人分析的生日必須符合中央資料。

中央會員沒有生日時，顯示「是否將 X年X月X日，新增為你本人的資料？」；取消不會寫入。確認後由 Life 後端使用會員 Access Token 呼叫官方 `PATCH /v1/me/profile`，只送 birthday，帶上最新 profile.version 的 If-Match。已存在生日或版本衝突時不覆寫、不自動重試。SDK 尚無可傳 If-Match 的 profile PATCH 方法，因此此處使用官方 OpenAPI 產生的型別及官方 API；沒有修改中央程式、設定或資料庫。

每次新的 AI 解讀保存姓名、生日、規則、血型、方向、命盤快照、文章、模型及時間。D1 先保存 pending，再確認 Battery 扣款，最後設為 ready；扣款失敗會移除 pending，紀錄查詢只呈現 ready。寫入失敗時不扣款；扣款成功後狀態更新暫時失敗會重試一次，仍失敗則明確提示使用者複製文章，絕不假稱已保存。

- `/records`：本會員的全部分析紀錄。
- `/mine`：明確標記為本人的分析。
- `/records/<id>`：歷史命盤及文章快照，可重新整理與上一頁。
- 每個列表與詳情查詢都用 user_id 篩選；管理員也不會因此取得其他會員紀錄。
- 游標包含時間與 ID，同一毫秒的紀錄不會漏掉。
- 上線前的解讀沒有保存文章，無法回補；自此版本起保存。

先在 staging 再 production 套用 `migrations/0002_member_records.sql`，只新增 Life 的資料表與索引，不修改原文資料。正式手機 App 需重新建置安裝才有新畫面。

模型清單顯示每百萬 tokens 的美元輸入／輸出價格、核對日期與官方連結；仍須按儲存才切換模型。Qwen3 30B 與 QwQ 32B 已公告 2026-11-20 退役，維持不列入推薦。
